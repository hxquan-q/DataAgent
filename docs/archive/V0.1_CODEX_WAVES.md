# DataAgent v0.1 — 多 codex 并行分工与波次计划

> 配套 [`V0.1_PRD.md`](./V0.1_PRD.md)。本文解决"如何把 18 个 task 安全拆给多个 codex CLI 并行执行"。
>
> 核心约束：**同一文件同一时刻只能一个 worker 写**（多 codex 共享同一 git 工作树会互相覆盖）。靠"文件所有权锁 + 分波次 + 状态/数据契约先行"解耦。

---

## 1. 并行模型（三件事必须先做）

1. **一 worker 一 git worktree**（推荐用 `/ccg:worktree` 或 `git worktree add`），彻底消除运行时文件覆盖。合并走 PR。
2. **文件所有权锁**：每个 worker 只能写自己"owns"列里的文件。共享文件（`Constant.java` / `DataAgentConfiguration.java` / `schema.sql` 等）由 `registry` worker 在 Wave -1 独占，他人**只读**。
3. **分波次启动**：同一 Wave 内的 worker 可同时开；下一 Wave 等上一 Wave 全部 merge 后再开（依赖 + 文件解锁）。

---

## 2. codex 操作规约（每个 worker prompt 必带）

```
- 工作区：你自己的 git worktree，分支 v0.1/<worker-name>。只改"owns"清单内的文件，其余只读。
- 必读：docs/dev/V0.1_PRD.md、docs/dev/V0.1_STATE_CONTRACT.md（registry 产出）、CLAUDE.md。
- 新建 .java 文件必须带 Apache 2.0 License 头（从任意现有 .java 顶部复制）。
- 注释用中文，风格对齐周边代码。
- 收尾前必须跑通：cd data-agent-management && ./mvnw spring-javaformat:apply spotless:apply && ./mvnw -q -Dtest=<你新增的测试> test
- 禁止：改 target/、node_modules/、vectorstore/、uploads/、.git/；禁止 git push、禁止动 main 分支、禁止改他人 owns 的文件。
- 新增状态键/表前，先查 V0.1_STATE_CONTRACT.md，已定义的直接用，缺了在文档备注并停下等 registry 补，不要自己改 Constant.java / DataAgentConfiguration.java / schema.sql。
```

## 3. 波次总表

| Wave | 可并行 worker 数 | 内容概要 | 启动条件 |
|---|---|---|---|
| **-1** | 1（串行） | registry：状态键 + 表 DDL + 契约文档 | 立即 |
| **0** | 6 | POC + 评测 + Skills Java 层 + 预聚合 + Schema 缓存 + 前端打字机 | Wave -1 merge |
| **1** | 4 | g2-ssr 服务 + FK 子图 + 自愈错误累积 + SQL 执行层(并发+校验) | Wave 0 merge + POC 通过门禁 |
| **2** | 3 | 图表渲染集成 + 技能预设数据 + 技能前端 UI | Wave 1 merge |
| **3** | 1~3 | 图文并茂+主题 + (可选)AST 护栏 + (可选)快路径 | Wave 2 merge |

> POC（chart-poc）是绘图链路的**门禁**：不通过则 Wave 1 的 chart-svc、Wave 2 的 chart-render 全部转方案（回退前端 ECharts 约束化 spec），届时重评估。

## 5. 状态/数据契约（registry 在 Wave -1 产出 `docs/dev/V0.1_STATE_CONTRACT.md`）

**新增状态键**（全部 `KeyStrategy.REPLACE`；列表型由节点读出→追加→写回，避免新增 strategy）：

| 键名 | 类型 | 用途 | 消费者 |
|---|---|---|---|
| `SQL_HEAL_ERRORS` | `List<String>` | 自愈累积错误历史 | sql-heal #13 |
| `CHART_IMAGE_MAP` | `Map<String,String>` | step→g2-ssr 图片 URL | chart-render #6 |
| `RESULT_SANITY_RETRY` | `Boolean` | 结果合理性重试标记 | sqlexec #14 |

**新增表**：

```sql
-- schema.sql & h2/schema-h2.sql（字段命名与现有表一致：下划线 + map-underscore-to-camel-case）
CREATE TABLE skill (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  name VARCHAR(128) NOT NULL,
  description VARCHAR(512),
  scope VARCHAR(32) NOT NULL,        -- report / sql / python ...
  triggers VARCHAR(512),             -- 触发关键词，逗号分隔，可空
  content LONGTEXT NOT NULL,         -- 技能正文/指令
  params_json TEXT,                  -- 预留参数
  enabled TINYINT DEFAULT 1,
  priority INT DEFAULT 0,
  display_order INT DEFAULT 0,
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  updated_at DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
);
CREATE TABLE agent_skill (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  agent_id BIGINT NOT NULL,
  skill_id BIGINT NOT NULL,
  enabled TINYINT DEFAULT 1,
  UNIQUE KEY uk_agent_skill (agent_id, skill_id)
);
```

> registry 同时在 `Constant.java` 加 skill 相关常量（如 prompt 注入用的 scope 标记），并把上述 3 个状态键注册进 `keyStrategyFactory`。

## 6. 各 worker 速记卡（可粘贴进 codex）

### Wave -1 · `registry`（串行先行）
**任务**：#1 无关；本波做状态/数据契约。
**owns**：`Constant.java`、`DataAgentConfiguration.java`(仅 keyStrategyFactory)、`schema.sql`、`sql/h2/schema-h2.sql`、`data.sql`、`sql/h2/data-h2.sql`、新建 `docs/dev/V0.1_STATE_CONTRACT.md`。
**做**：按 §5 加 3 个状态键 + skill/agent_skill 两表（MySQL + H2 两份 DDL）；产出契约文档列出全部键/表/字段供他人引用。
**验收**：`./mvnw -q compile` 通过；H2 profile 启动建表成功；契约文档完整。
**完成后**：merge → 触发 Wave 0 全员启动。

### Wave 1（4 并行，需 Wave 0 merge + chart-poc 通过）

**`chart-svc` [#3]**
owns：`g2-ssr/` 定稿 + `docker-file/` + `application.yml`(g2-ssr 段)。
做：在 chart-poc 基础上做正式 Node wrapper（HTTP POST `{type,axis,data,path}` → PNG/SVG 落盘返回 URL，超时 15s，中文字体）+ Docker 化（cairo/pango）+ `/health` + 降级钩子。验收：容器起、健康检查通、渲染样例图。

**`fk-subgraph` [#12]**
owns：`workflow/node/SchemaRecallNode.java` + 新建 `util/FkSubgraphBuilder.java`。
做：top-K 表召回后，用物理外键 + `logical_relation`（逻辑外键 mapper 已存在）扩展桥接表（≤6 跳邻域），只把相关表 DDL 注入 prompt。读 Constant 键（registry 提供）。验收：多表 JOIN 召回 F1↑；token↓。

**`sql-heal` [#13]**
owns：`workflow/node/SqlGenerateNode.java` + `prompts/sql-error-fixer.txt`。
做：每轮自愈把新错误追加进 `SQL_HEAL_ERRORS`（读出→追加→写回，REPLACE 策略），注入 sql-error-fixer.txt 让 LLM 看全部历史错误。受 `maxSqlRetryCount` 兜底。验收：自愈成功率↑；回环不发散。

**`sqlexec` [#10+#14]（合并：同属 SQL 执行文件区）**
owns：`workflow/node/SqlExecuteNode.java`、`workflow/node/PlanExecutorNode.java`、`util/PlanProcessUtil.java`、`dto/datasource/SqlRetryDto.java`。
做：#10 识别 Plan 步骤依赖图，无依赖步骤用 `dbOperationExecutor` 并发执行；#14 执行后空结果/异常行数 → `RESULT_SANITY_RETRY` 触发一次有界重试。验收：多步独立计划 wall-clock↓；错结果被纠正比例可观测；有依赖仍串行正确。

## 6. 启动清单（给操作者）

1. 先单独跑 `registry`（Wave -1），merge 后确认 `V0.1_STATE_CONTRACT.md` 存在。
2. 为 Wave 0 的 6 个 worker 各开一个 worktree：`git worktree add ../da-chart-poc -b v0.1/chart-poc`（其余同理）。
3. 每个工作树里启动 codex，粘贴：§2 操作规约 + 该 worker 速记卡。
4. `chart-poc` 出结果先评审：通过 → 继续 Wave 1 chart-svc；不通过 → 停绘图链路，转方案。
5. 同 Wave 全部 PR merge 后，再开下一 Wave 的 worktree。
