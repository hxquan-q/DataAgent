# DataAgent v0.1 PRD — 性能 / 速度 / 准确度 / 报告 / 绘图优化

> 本文基于 [`SPRING_AI_GRAPH_IMPLEMENTATION_PLAN.md`](./SPRING_AI_GRAPH_IMPLEMENTATION_PLAN.md)（控制论蓝图 M1–M4）与 [`docs/research/`](../research/) 8 张源码卡，结合用户 v0.1 明确优先级裁剪而成。
>
> 控制论骨架：η₁ 分类定方法 → η₅ 先稳后优 → η₄ 主导因素 → η₆ 有界 → η₇ 可验证。
> 工程纪律：抄设计不抄代码；最小改动复用现有基础设施；每个工作流有可验收度量。

## 0. 范围与边界

**做什么（用户 6 优先级）**：性能、速度、准确度、报告质量、报告格式可定制（Skills）、绘图能力（图文并茂）。

**不做（v0.1 显式排除）**：
- 多租户 / 行级权限（用户明确）。
- SQL 样例训练库反哺（vanna M3，依赖数据积累）→ **v0.2**。
- Neo4j 图依赖（v0.1 用内存 FK 子图）。
- 从零重写。

**基线**：当前 dev 分支，16 节点 DAG + HITL + Python + ECharts 报告。

## 1. 现状诊断（根因，已代码核实）

| 优先级 | 现状根因 | 控制论归类 |
|---|---|---|
| 速度 | 端到端 8–10 次串行 LLM 调用；Schema 元数据每查重抽；相同文本重复 embedding | η₂ 冗余 |
| 性能 | 多步计划独立 SQL 步骤串行；打字机 180 字符/秒，LLM 完成后仍需 ~28s "动画完毕" | η₆ 无界等待 |
| 准确度 | Schema 召回无 FK 子图扩展（多表 JOIN 召回不全）；自愈不累积历史错误 | 域Ⅲ 闭环信息不全 |
| 报告质量 | 报告 prompt 直接灌 raw `step_N` JSON，LLM 自算指标 | 域Ⅴ 信号未降噪 |
| 格式可定制 | 仅 `{optimization_section}` 自由文本，无技能化封装 | η₁ 单一形态 |
| 绘图 | 报告 LLM **手写完整 ECharts Option**，质量随机、主题不一致、固定 400px；与 result-set 的约束化 spec 路径（`data-view-analyze`+`DisplayStyleBO`）割裂 | η₄ 渲染未确定性下沉 |

## 2. 目标与验收度量（η₇）

| 维度 | 目标 | 度量 |
|---|---|---|
| 速度 | 静态数据零重算；简单查询快路径 | 同 agent 二次查询命中缓存耗时 ↓ ≥40% |
| 性能 | 独立步骤并发；流结束即可交互 | 多步计划 wall-clock ↓；流结束到可交互 < 1s |
| 准确度 | 多表 JOIN 召回补全；自愈带历史错误 | 多表场景 SQL 执行成功率 ↑；自愈成功率 ↑ |
| 报告质量 | 灌预聚合摘要而非原始 JSON | 报告幻觉率 ↓（人工抽检） |
| 格式可定制 | 报告"技能"按 agent 切换结构/图表策略/语气 | ≥3 内置技能可应用 |
| 绘图 | g2-ssr 服务端渲染 + 图文并茂保障 | 图表渲染成功率 ≥98%；有数值数据时含图率 100% |

## 3. 两条决策（已与用户确认）

### 3.1 绘图：引入 g2-ssr Node 微服务

**机制**：LLM 只产**图表配置 spec**（type + 字段映射 + 数据），渲染下沉到独立 Node 微服务，产出 PNG（或 SVG），报告以 `![title](url)` 内嵌 → **真实图文并茂**，且独立于前端 JS、可用于 HTML/PDF 导出。

**契约**（抄 SQLBot `g2-ssr/app.js`）：HTTP POST `{type, axis, data, path}` → `@antv/g2-ssr` `createChart(options).exportToFile(path)` → PNG 落盘 → 返回 URL；超时 15s；中文字体内嵌。

**风险与降险（置信度 Medium）**：
- 官方 `@antv/g2-ssr` 仅 v0.0.4（实验阶段）→ **POC 先行**，验证基础+进阶图表类型与中文渲染后再正式投入；备选 `@berryv/g2-ssr-node`（AntV 核心成员 pearmini 维护）。
- `node-canvas` 原生依赖（cairo/pango）→ Docker 基础镜像处理。
- 引入 Node 运行时到 Java 栈 → 容器化 + 健康检查 + **降级回退**（服务不可用时回退现有前端 ECharts，不阻断报告）。

**来源**：[`docs/research/sqlbot.md`](../research/sqlbot.md) §亮点 5；[G2 SSR 官方文档](https://g2.antv.antgroup.com/en/manual/extra-topics/ssr)；[antvis/g2-extensions](https://github.com/antvis/g2-extensions)。

### 3.2 报告定制：SKILL.md 规范的通用技能框架

**规范来源**：OpenAI skill = 可复用工作流 bundle，以 `SKILL.md` 清单为入口；Claude Code skill = frontmatter（`name`/`description`）+ 正文，按描述匹配触发。两者收敛到「manifest + 打包资源 + 元数据触发」。

**v0.1 落地**：
- Skill = `{name, description, scope, triggers, content/instructions, params?}` 的 DB 记录（`skill` 表 + `agent_skill` 绑定），UI 可编辑。
- `scope` 决定注入哪个节点 prompt（`report` / `sql` / `python` / …），**泛化现有 `{optimization_section}`** 为多作用域技能注入。
- 内置 ≥3 预设（管理驾驶舱 / 数据探索 / 深度分析）。

**来源**：[OpenAI Skills in API Cookbook](https://developers.openai.com/cookbook/examples/skills_in_api)；[Skills in ChatGPT](https://help.openai.com/en/articles/20001066-skills-in-chatgpt)；Claude Code 本地 SKILL.md 范式。

### WS2 · 速度与性能（P0）
| ID | 动作 | 复用点 |
|---|---|---|
| 2.1 | **Schema 元数据缓存**：按 `(datasourceId, 选中表集 hash)` 缓存，schema 变更失效 | `SchemaService`/`TableMetadataService` |

## 6. 风险与置信度

| 项 | 风险 | 置信度 | 缓解 |
|---|---|---|---|
| g2-ssr 库成熟度 | 中（v0.0.4 实验） | **Medium** | POC 先行；备选 `@berryv/g2-ssr-node`；降级回退前端 ECharts |
| node-canvas 原生依赖 | 中 | Medium | Docker 基础镜像 + 中文字体 |
| Skills 范围蔓延 | 中 | Medium | 内置 3 预设优先，自定义编辑留 v0.2 |
| 缓存失效正确性 | 中（脏 schema） | Medium | 版本键失效 + 手动刷新接口 |
| spec 约束化丧失灵活性 | 低 | High | WS1.4 逃生舱保留 raw 块 |
