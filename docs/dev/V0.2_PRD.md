# DataAgent v0.2 PRD — 范式迁移 NL2Semantic2SQL

> 本文基于 [`data-agent-architecture-design.md`](../data-agent-architecture-design.md)（目标 NL2Semantic2SQL 北极星）、[`NL2SQL_AGENT_CYBERNETICS.md`](./NL2SQL_AGENT_CYBERNETICS.md)（控制论 η₁–η₇ 推导）、[`SPRING_AI_GRAPH_IMPLEMENTATION_PLAN.md`](./SPRING_AI_GRAPH_IMPLEMENTATION_PLAN.md)（M1–M4 蓝图）与 [`docs/research/`](../research/) 8 张源码卡综合而成。
>
> **v0.1 成果分布在两个分支**（已 git 核实）：`v0.1-integration`（CI 全绿，已 push `origin/v0.1-integration`）含 AST 护栏 / g2-ssr 图文并茂 / Skills 全栈 / 并发执行；`v0.1/eval`（当前所在）仅含 16 节点 + eval 基线（`DataAgentBaselineEvalTest` + `BASELINE.md`）。merge-base 为 `1ccf8ba`（= v0.1/eval HEAD），即 `v0.1-integration` 从 `v0.1/eval` 派生且领先。**v0.2 的工作基线 = `v0.1-integration`**（见 §0.3 前置动作）。本 PRD 是其上的**范式级增量**。
>
> 控制论骨架：η₁ 分类定方法 → η₅ 先稳后优 → η₂ 最少自由度 → η₄ 主导因素 → η₆ 有界 → η₇ 可验证。
> 工程纪律：抄设计不抄代码；最小改动复用现有基础设施（StateGraph / `semantic_model` / `logical_relation` / g2-ssr / Skills）；每个里程碑有可验收度量。

## 0. 范围与边界

### 0.1 做什么（用户拍板：范式 B + 4 支柱）

**范式决策（η₁）**：从 **NL2SQL**（LLM 直出 SQL，靠校验/重试兜底）迁移到 **NL2Semantic2SQL**（LLM 只从候选语义对象**选择**，后端**受控拼装** SQL）。

> 设计哲学（架构设计文档）："将概率生成转化为确定性构建。模型做语义理解，系统做 SQL 生成——人把轨道铺好，模型只负责把乘客放到正确车厢。"

**4 个投资支柱**：

| 支柱 | 控制论依据 | 抄谁 | 一句话 |
|---|---|---|---|
| ① AST 安全护栏 + 表名白名单 | η₅ 先稳后优（纵深防御） | SQLBot `check_sql_read()` | jsqlparser 三层只读校验 + AST 重解析真实表名 |
| ② 语义层 / 指标口径 | η₂ 最少自由度 + η₁ 收敛选择空间 | 架构设计文档 + datafoundry | 四表（复用 `semantic_model` 作 DIM + 新增 metric/metric_version/alias） |
| ③ SQL 样例训练库 | 域Ⅴ§16 在线辨识（自适应） | vanna 三库训练 | 成功 SQL 反哺 → few-shot 召回 → 越用越准 |
| ④ 证据链 / Run Trace 可回放 | η₇ 可验证 + datafoundry | datafoundry checkpoint DAG | 每个结论可复盘：语义对象→SQL→结果→口径 |

### 0.2 不做（v0.2 显式排除）

- **跨系统 JOIN 查询**（架构设计文档自己也放 Phase 2）→ v0.3。
- **完整多租户 / RBAC 控制平面**（datafoundry 企业控制平面级）→ v0.3；v0.2 只做**单租户行级权限改写**作为 AST 护栏的延伸（可选）。
- **从零重写**：v0.1 的 16 节点 Graph / HITL / Python 分析 / g2-ssr / Skills 全部复用。
- **删除现有 NL2SQL 链路**：保留为显式 opt-in「专家/原始模式」（默认关），作为 η₃ 线性化有效区间外的安全网，**非默认流程**。

### 0.3 基线（两分支事实，已 git 核实）

| 分支 | 内容 | 状态 |
|---|---|---|
| `v0.1/eval`（当前所在） | 16 节点 DAG + HITL + Python + ECharts 报告 + **eval 基线** | ❌ 无 AST 护栏 / 无 g2-ssr 接线 / 无 Skills 接线 |
| `v0.1-integration`（**v0.2 起点**） | 上述全部 + **AST 护栏 + g2-ssr 图文并茂 + Skills 全栈 + 并发执行** | ✅ CI 全绿，领先 v0.1/eval |

> **⚠️ v0.2 前置动作**：以 `v0.1-integration` 为工作基线（新建 `v0.2/*` 分支从其派生，或先合并）。当前 `v0.1/eval` 仅承载 eval 基线度量，不含 v0.1 全部能力。详见 [`V0.1_PRD.md`](./V0.1_PRD.md) 与 [`V0.1_CODEX_WAVES.md`](./V0.1_CODEX_WAVES.md)。

## 1. 现状诊断（根因，已代码核实）

| 维度 | 现状根因 | 控制论归类 | v0.2 对策 |
|---|---|---|---|
| **范式** | LLM 直出 SQL，口径由模型即兴推导，不可审计、不可复现 | η₁ 选择空间过大 | 语义层收敛：LLM 选指标，系统拼 SQL |
| **口径一致** | 同一"金额"每次查询可能不同 SQL，无版本化口径 | η₃ 线性化失灵 | `metric_version` 口径版本 + `is_default` + 反问消歧 |
| **业务黑话** | `business_knowledge` 是自由文本，未映射到结构化 code | η₂ 自由度冗余 | `alias` 表：alias_text → target_code + match_type + priority |
| **可审计** | Langfuse 只有节点级 trace，无 run 级「语义对象→SQL→结果→口径」证据链 | η₇ 不可复盘 | `query_log` 证据链 + checkpoint DAG 可回放 |
| **自适应** | 每次从零猜，成功经验不沉淀 | 域Ⅴ§16 无辨识 | `sql_examples` 训练库反哺（v0.1 延后项） |
| **安全纵深** | `v0.1-integration` 已实现 AST 护栏（jsqlparser 三层），但未覆盖受控拼装产物的模板片段 + 未做表名白名单差集 | η₅ 纵深不足 | 扩展现有 AST 护栏 + 表名白名单贯穿 BuildSQL 产物 |

> **现有资产复用率高的关键**：`semantic_model`（字段级 business_name 映射）天然就是架构文档 DIM 层的雏形；`logical_relation`（逻辑外键图）是受控拼装做 JOIN 路由的基础。v0.2 只需**叠加指标层**，不动字段层。

## 2. 目标与验收度量（η₇）

| 维度 | 目标 | 度量方式 | 里程碑 |
|---|---|---|---|
| **口径一致** | 标准指标查询口径零漂移 | 同指标多次查询 SQL 归一化一致率 100% | M2 |
| **准确度** | 标准指标查询语义正确率 ↑ | Golden Query Set 语义正确率 ≥92%（v0.1 基线对比） | M3 |
| **安全** | 危险 SQL 零放行 | 红队用例集（DML/DDL/越权表/危险函数）拦截率 100% | M1 |
| **可审计** | 每个结论可回放 | run trace 覆盖率 100%（语义对象+SQL+结果+口径+耗时） | M4 |
| **自适应** | 越用越准 | 同题二次命中率随样本量单调上升曲线 | M3 |
| **覆盖** | 语义层未覆盖时优雅降级 | 未覆盖查询触发反问/告知率 100%（不硬猜） | M2 |
| **终止性** | 有限步收敛，零发散 | 无超时/死循环（重试/超时/行数/成本全局有界） | M1 |

## 3. 核心决策（已与用户确认）

### 3.1 范式：NL2Semantic2SQL（B 路线）

```
用户问 → [上下文过滤候选] → [LLM 选指标(非生成)] → [完整性+字段校验]
                                                              ↓ 不完整→反问
                                                         [受控SQL拼装(非LLM)]
                                                              ↓
                        [AST护栏] → [Data Gateway 执行] → [结论] → 报告
```

- LLM 只做**语义理解**（选指标/维度/过滤/时间范围），不做 SQL 生成。
- 后端根据 `SemanticObject` + `metric.sql_template` / 拼装规则**确定性构建** SQL。
- 未覆盖 → 反问澄清或友好告知「暂不支持，建议…」（**不硬猜、不静默回退 NL2SQL**）。

### 3.2 语义层 = 现有字段层 + 新增指标层（η₂ 最少自由度）

| 层 | 表 | 状态 | 角色 |
|---|---|---|---|
| 维度层 DIM | `semantic_model`（字段级 business_name） | **复用** | 物理字段 → 业务名/同义词，GROUP BY 维度来源 |
| 别名层 ALIAS | `business_knowledge` + 新增 `alias` 映射 | **扩展** | 业务黑话 → 结构化 code（metric/dim/ver/filter） |
| 关系层 | `logical_relation`（逻辑外键图） | **复用** | 受控拼装 JOIN 路由 |
| **指标层 METRIC** | **新增 `metric`** | **新建** | 指标定义（编码/聚合字段/聚合函数/来源表/时间字段） |
| **口径层 METRIC_VER** | **新增 `metric_version`** | **新建** | 同指标多口径版本 + 默认口径 + 口径说明 |
| 证据层 | **新增 `query_log`** | **新建** | 语义对象+SQL+结果+口径+耗时（审计+反哺+回放） |
| 训练层 | **新增 `sql_examples`** | **新建** | 成功 SQL 向量库（第三路 few-shot 召回） |

### 3.3 受控拼装引擎（BuildSQL，非 LLM）

输入 `SemanticObject`，输出参数化 SQL：

```
SELECT {dim_columns}, {metric.agg_func(metric.agg_field)}
FROM   {metric.source_table}
[JOIN {bridge_tables} ON ... ]        ← logical_relation 路由，≤2 跳
WHERE  {time_range} AND {filters} AND {row_perm}
GROUP BY {dim_columns}
[ORDER BY ...] [LIMIT {N}]
```

- 全部参数化（PreparedStatement），零字符串拼接注入面。
- 产物过 AST 护栏二次校验（η₅ 纵深）。

### 3.4 4 支柱落点

| 支柱 | 落点 | 抄源 |
|---|---|---|
| ① AST 护栏 | `SqlGuardNode`（贯穿 BuildSQL 产物 + 训练库反哺前 + 专家模式） | [sqlbot.md](../research/sqlbot.md) `check_sql_read()` L777-842 |
| ② 语义层 | `SemanticLayerLoader` + `SemanticContextFilter` + `SemanticParseNode` + `BuildSQLNode` | 架构设计文档 §5/§6 + datafoundry metadata |
| ③ 训练库 | `sql_examples` 表 + 向量索引 + `EvidenceRecallNode` 第三路召回 + 成功反哺 | [vanna.md](../research/vanna.md) 三库 |
| ④ 证据链 | `query_log` + Run Trace DAG（checkpoint 可回放） | datafoundry semantic trace |

## 5. 实施顺序（η₅ 先稳后优 + 依赖）

```
Phase 0  地基：  WS0.1 表+Loader → WS0.2 热加载 → WS0.3 管理UI → WS0.4 种子
Phase 1  安全：  WS1.1 AST三层 → WS1.2 表名白名单 → WS1.3 全局有界   ← η₅ 必须先于拼装
Phase 2  范式：  WS2.1 候选过滤 → WS2.2 语义解析 → WS2.3 校验 → WS2.4 受控拼装 → WS2.5 反问
Phase 3  网关：  WS3.1 DataGateway → WS3.2 证据链 → WS3.3 Run Trace
Phase 4  自适应：WS4.1 训练库 → WS4.2 few-shot召回 → WS4.3 治理
贯穿     评测：  WS5.1 Golden→WS5.2 红队→WS5.3 门禁（M0 起即建立）
可选     安全网：WS6.1 专家模式
```

| 里程碑 | 能力 | 验收度量（η₇） |
|---|---|---|
| **M1 安全硬门槛** | AST 三层 + 表名白名单 + 全局有界 | 危险 SQL 100% 拦截；零发散 |
| **M2 范式核心** | 语义层 + 受控拼装 + 反问 | 口径一致率 100%；标准指标语义正确率 ≥92%；未覆盖反问率 100% |
| **M3 自适应** | 训练库反哺 + Golden 扩充 | 同题二次命中率↑；准确率随样本单调上升 |
| **M4 可审计** | Data Gateway + 证据链 + Run Trace | run trace 覆盖 100%；可回放 |

> **顺序不可乱**：M1 必须先于 M2。没有 AST 护栏的受控拼装 = 模板片段被污染时直打生产库（违反 η₅）。

## 6. 风险与置信度

| 项 | 风险 | 置信度 | 缓解 |
|---|---|---|---|
| 语义层冷启动（指标配置量大） | 高 | Medium | demo 数据源先配 ≥8 指标验证闭环；管理 UI 降低配置门槛；专家模式兜底 |
| 受控拼装覆盖有限（复杂查询拼不出） | 中 | Medium | 未覆盖→反问/告知（不硬猜）；专家模式 opt-in；架构文档 Phase 2 才跨系统 JOIN |
| LLM 选错指标（候选列表噪声） | 中 | Medium | ContextFilter 收敛候选 + JSON Schema 约束 + 字段校验 + 反问 |
| `jsqlparser` 7 方言覆盖 | 中 | Medium | 方言不全降级正则黑名单兜底（同 v0.1） |
| 训练库脏数据污染 | 中 | High | 只反哺执行成功 + 人工审核开关 + hash 去重 |
| 范式迁移回归风险 | 中 | Medium | 保留 v0.1 NL2SQL 链路为专家模式（默认关），灰度切换 |
| 口径版本歧义反问过频（体验） | 低 | Medium | `is_default` 默认口径 + priority 优先级 + 反问频次有界 |
